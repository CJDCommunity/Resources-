
🚀 Kotak Mahindra Bank | L3 Java Backend Developer Interview Questions  
  
Preparing for an L3 Java Backend Developer interview?  
  
At senior levels, interviewers expect more than Core Java definitions. They want to understand how you design scalable systems, handle concurrency, maintain data consistency, and troubleshoot production-level issues.  
  
Here are important questions reported in candidate interview experiences. 👇  
  
🔥 1. System Design & Architecture  
  
* Design a Payment Processing System.  
* Design a scalable Banking Transaction System.  
* How would you build a file processing system using Kafka?  
* How do you ensure consistency across microservices?  
* Explain the Outbox Design Pattern.  
* How do you handle distributed transactions?  
* Strong Consistency vs Eventual Consistency.  
* Explain CAP Theorem with real-world examples.  
  
☕ 2. Advanced Java & Concurrency  
  
* How does ConcurrentHashMap work internally?  
* Explain the Java Memory Model.  
* How do you identify and prevent deadlocks?  
* Synchronized vs ReentrantLock.  
* Explain CompletableFuture and its use cases.  
* How do you handle race conditions?  
* How do Virtual Threads work?  
  
🌱 3. Spring Boot & Microservices  
  
* How does Spring transaction management work internally?  
* Explain transaction propagation and isolation.  
* How does the Spring Security filter chain work?  
* How do you implement idempotency in payment APIs?  
* How do you handle retries, timeouts, and circuit breakers?  
* How do you prevent duplicate event processing?  
* How do you handle failures between two microservices?  
  
⚡ 4. Kafka & Distributed Systems  
  
* What happens when a Kafka consumer goes down?  
* How does Kafka handle message ordering?  
* Explain consumer groups and partition reassignment.  
* At-most-once vs At-least-once vs Exactly-once delivery.  
* How do you handle duplicate Kafka messages?  
* What is backpressure in distributed systems?  
* When would you use distributed locks?  
  
🗄️ 5. Database & Performance  
  
* How do database indexes work internally?  
* Optimistic Locking vs Pessimistic Locking.  
* How do you prevent lost updates in banking transactions?  
* How do you optimize queries on millions of records?  
* How do you troubleshoot high database connection usage?  
  
🏗️ 6. Low-Level Design  
  
* Design a Food Delivery Application.  
* Design a Banking Transaction Service.  
* Design a File Processing System.  
* Explain SOLID principles with practical examples.  
* Where would you use Factory, Strategy, and Observer patterns?

🚨 Kotak Mahindra Bank | SDE-2 Java Backend Interview Experience  
  
Sharing another interesting Java Backend Developer interview experience for candidates preparing for product-based and high-paying backend roles.  
  
📌 Company: Kotak Mahindra Bank  
💼 Role: SDE-2 – Backend (Java)  
🎯 Experience: Under 4 YOE  
💰 Compensation: 25–30 LPA  
🔄 Process: 3 Technical Rounds + HR  
  
🔥 Round 1 — Bar Raiser | 90 Minutes  
  
The first round covered DSA + Kafka + LLD.  
  
🔹 DSA: Travel Pass problem — 1-day, 7-day and 30-day passes with different costs; find the minimum expenditure.  
  
🔹 Kafka:  
• Producers & Consumers  
• Partitions  
• Offsets  
• Consumer Groups  
• Offset Management  
• Rebalancing  
  
🔹 LLD: Design a system with clear class responsibilities and make it extensible without breaking existing callers.  
  
💻 Round 2 — DSA + Project  
  
🔹 Given a JSON string, count the number of nested objects.  
  
🔹 Given n up to 10^9, calculate 2^n and repeatedly sum its digits until a single digit remains — requiring an optimized mathematical approach instead of brute force.  
  
🔹 Deep dive into the current project:  
• Architecture & design decisions  
• Challenges faced  
• Technical decisions  
• What could be improved or changed  
  
🧩 Round 3 — LLD in an IDE  
  
A Music Player had to be designed and implemented with:  
  
▶️ Play  
⏭️ Next  
⏮️ Previous  
🔂 Repeat One  
🔁 Playlist Repeat  
  
The expectation was working code, not just a class diagram.  
  
The follow-up question focused on reducing too many conditional branches using a suitable Design Pattern.  
  
💡 Strategy Pattern was suggested, while State Pattern was the expected approach.  
  
👔 HR Round  
  
All three technical rounds were cleared.  
  
However, since the candidate had under 4 years of experience, the role was revised from SDE-2 to SDE-1.  
  
📌 Final Status: Declined  
  
🎯 Key Takeaway  
  
This is a great example of how backend interviews at higher compensation levels can go beyond Core Java.  
  
You should be prepared for:  
  
☕ Advanced Java  
🧠 DSA & Optimization  
📨 Kafka internals  
🏗️ Low-Level Design  
🎨 Design Patterns  
💼 Deep Project Discussions  
⚡ Writing working code under interview conditions  
  
And most importantly — don’t just prepare the definition of a design pattern. Be ready to identify when and why you would use it.
